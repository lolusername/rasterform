# Keeping agent-assisted code easy to change

Rasterform engineering review · November 10, 2026 · source revision `5e9564a`

Rasterform's renderer knows about five animation behaviors. Its desktop download handler knows about four. Both pass their own tests, yet a completed export tells the artist to run it again. The extra maintenance work comes from having to discover every copy of one decision. On the next change, ask a second person to find that decision, predict what happens on failure, and verify the result where the artist encounters it.

## Six reproducible findings in Rasterform

**1. A clean checkout fails both build checks.** With dependencies installed from the committed locks, `npm run build` and `npm run desktop:check` both failed with TypeScript error `TS7016` for Three.js. Installing only `@types/three@0.180.0` in a disposable copy made both commands pass. This blocks the standard web build and desktop type check from source. The existing release checklist already has the right regression checks, including the clean install. [Root dependency manifest](../package.json#L37) · [Release checks](DESKTOP.md#L125)

**2. Expand reports a failed save after Electron writes the ZIP.** Import a 256 × 4 grayscale ramp, choose **Strata → Living Form → Expand**, and export a one-second 2K loop at 12 fps. Electron completed the download. The manifest and all 12 PNG entries passed `unzip -t`. After ten seconds the editor reported that macOS had failed to finish saving. The filename recognizer omits `expand`. Test every supported behavior through the real filename builder and trusted-download check, plus one desktop save where the UI outcome must agree with the completed file. Keep the origin and job-owner checks. [Supported behaviors](../src/lib/living-form.ts#L9) · [Filename builder](../src/App.vue#L2197) · [Electron recognizer](../electron/main-helpers.ts#L14)

**3. Wireframe GLB export drops edges.** Export the same raised relief as a regular GLB and a Wireframe GLB. At default mesh detail, the triangle file had 23,408 distinct edges. The wire file omitted 7,920 of them and contained 7,744 zero-length segments. The exporter interprets consecutive triangle indices as pairs of line endpoints. Even a two-triangle quad exposes the error. Decode both files and compare sets of unordered endpoint pairs, including the diagonal. Also reject segments with identical endpoints. [GLB export](../src/lib/export.ts#L61)

**4. Photo mode writes midtones too bright.** Import an opaque 32 × 32 `#808080` PNG, choose **Raised relief → Photo**, then export a GLB using **Current appearance**. Its `COLOR_0` was 0.50196 per channel. glTF expects a linear value, about 0.21586 for this swatch. The sampler divides the sRGB byte by 255 and passes that value into the shared preview and export geometry. Test a mid-gray pixel through to the saved file. Black and white alone would both pass. Rasterform already has the required transfer function. [Sampler](../src/lib/mesh-sampling.ts#L13) · [Geometry assembly](../src/lib/three.ts#L87) · [Existing conversion](../src/lib/channels.ts#L12) · [glTF specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#meshes) · [Three.js color management](https://threejs.org/manual/pages/color-management.html)

**5. A Strata preset resets a manually zoomed camera.** With the demo image, set mesh detail to 20, choose Strata, zoom in, then apply **Ink emboss**. In Chromium the camera distance went from 4.410 to 3.501 under the zoom and back to 4.410 on applying the preset. The status reported that the camera was kept. Strata auto-fits changing stacks, while the preset promises to preserve framing. Test those two actions separately. For the preset, compare the authored camera and target before and after the mesh rebuild. [Preset promise](EDITOR_UX.md#L37) · [Strata fitting policy](STRATA.md#L10) · [Mesh update that moves the camera](../src/components/ThreePreview.vue#L254)

**6. Mesh health accepts a pinched vertex as ready for STL.** Give `inspectTopology` two closed tetrahedra sharing exactly one vertex. It returns one component, zero boundary edges, zero non-manifold edges and `watertight: true`. The editor uses that result to enable STL. The shared vertex has two disconnected face fans, so the surface is non-manifold there. This was a synthetic input to the production validator. Its frequency in meshes made in the editor is unknown. Add the touching pair as a negative case and a single tetrahedron as a positive case. [Readiness predicate](../src/lib/topology.ts#L98) · [Editor status](../src/App.vue#L2675)

**Verification scope.** All 442 tests in 57 files passed, including Blender integration tests. The editor comparison checks also passed in Chromium. The desktop export reproductions used a locally staged Electron app built from the audited sources, with save destinations redirected to a temporary directory. The GLB measurements came from the saved binary files. The installed release binary was outside this review. These observations establish defects at this revision. Their authorship is unknown.

## What current studies actually measured

**Repeated extensions can accumulate redundant code.** SlopCodeBench gave 15 agents 36 problems with 196 successive checkpoints. Its redundancy measure rose in 75.5% of trajectories and its measure of concentrated complexity rose in 77%. Explicit quality instructions improved the starting point, with little effect on the subsequent rate of deterioration. Those percentages count trajectories on a Python benchmark. Human reading time requires a different measurement. [Orlanski et al., SlopCodeBench, revised May 2026](https://arxiv.org/abs/2603.24755v2)

**Earlier regressions can account for much of the next developer's difficulty.** SWE-Maintain compared 1,996 paired follow-up events from 50 Python repositories. The same agents resolved 5.6 percentage points fewer later tasks on their own earlier changes than on developer changes. Requiring all earlier tests to pass widened the gap to 14 points. When inherited tests already passed and the next task was still unsolved, the estimate was +2.7 points with a 95% interval from −0.5 to +6.1. That subset is compatible with no difference. CodeThread, a separate four-agent study, also singled out input validation and error handling as signals that conventional complexity measures often missed. [Pan et al., SWE-Maintain, October 2026 preprint](https://arxiv.org/abs/2610.14768) · [Patel et al., CodeThread, September 2026 revision](https://arxiv.org/abs/2606.21804v2)

**A human handoff study found no detectable slowdown.** In a preregistered two-phase study with 151 participants, 75 developers performed a follow-up change on someone else's Java application without AI assistance. The authors found no statistically significant downstream difference in completion time or code quality between the assisted and unassisted origins. A November observational study of 260 student repositories found that final codebases roughly tripled in size across cohorts. Individual AI use was unmeasured, so those counts cannot identify the cause. Time a human handoff on your own code to learn where comprehension breaks down. [Borg et al., *Empirical Software Engineering*, June 2026](https://link.springer.com/article/10.1007/s10664-026-10889-1) · [Shakil et al., November 2026 preprint](https://arxiv.org/abs/2611.07297)

**The value of extra harness steps depends on the task and model.** The harness is the software that supplies context, tools, checks and feedback to the model. Across 176 matched configurations and four models, the benefits of planning, predefined tools and context management varied with model capability and context budget. The study measured task performance and cost. A separate experiment found that repository instruction files increased inference cost by over 20% on average without a consistent task-success gain. Give agents the project-specific commands, decisions and failure examples they need. Test each proposed addition against a real follow-up task. [Fan et al., harness-design study, September 2026 preprint](https://arxiv.org/abs/2609.20804) · [Gloaguen et al., repository context study](https://www.sri.inf.ethz.ch/publications/gloaguen2026agentsmd)

## Three ways to reason about a change

### Category theory gives a precise question for adapters

In a commutative diagram, two paths from the same input to the same output agree. For a simple indexed triangle mesh, compare these two paths. Define edge equality to ignore endpoint order and repeated edges. Check for zero-length lines separately so normalization cannot conceal them.

```text
triangle mesh ─── derive its three edges per face ───→ set of edges
      │                                                       ↑
      └── export a wireframe GLB ──→ decode its line pairs ───┘
```

The paths disagree in the saved Rasterform file. A test that asks the encoder whether it returned bytes will miss this. Give the expected path a small, independent implementation. The same reasoning applies to a project save and reopen. For a supported document, `decode(encode(document)) ≈ document` should compare asset bytes, authored settings and camera values within a declared tolerance. A freshly decoded image can have equal contents and a new object identity. Write down the equivalence before writing the assertion. Enumerate small domains such as the five behaviors. Generate cases when the space of inputs is large. [Fong and Spivak, *Seven Sketches in Compositionality*](https://ocw.mit.edu/courses/18-s097-applied-category-theory-january-iap-2019/resources/18-s097iap19textbook_pdf/) · [Claessen and Hughes, QuickCheck](https://research.chalmers.se/en/publication/237427)

### Lambda calculus tells you when substitution is safe

In call-by-value evaluation, `(λx. pair(x, x)) v` reduces to `pair(v, v)` when `v` is an already evaluated value. Replacing two uses of a saved path with two calls to a file chooser opens two dialogs. Replacing a captured camera with repeated reads of the live camera can give frames different views. Keep computations that transform values callable with explicit inputs. Capture mutable inputs once when the operation requires a snapshot. Rasterform's loop exporter already clones the camera when export begins. [Plotkin, *Call-by-name, call-by-value and the λ-calculus*](https://homepages.inf.ed.ac.uk/gdp/publications/cbn_cbv_lambda.pdf) · [Moggi, *Notions of computation and monads*](https://maxsnew.com/docs/moggi91.pdf) · [Existing export snapshot](../src/components/ThreePreview.vue#L205)

For an effect such as saving, specify which observations establish completion. Electron can hear that the renderer finished packaging and that the native download completed in either order. Success requires both events for the same job, and completion should be reported once. Exercise both orderings and an interrupted write. The existing lifecycle object already owns this decision. The Expand case shows where its input can go missing. [Native export lifecycle](../electron/long-export-lifecycle.ts#L41) · [Lifecycle tests](../electron/long-export-lifecycle.test.ts#L38)

### Topology supplies a counterexample to a plausible rule

On a closed triangulated manifold surface, every edge belongs to two faces **and** the faces around each vertex form one cyclic fan. The *link* is the ring traced opposite the vertex through its incident triangles. At the pinch there are two separate rings. Checking the link would catch what counting faces per edge missed. The fixture's Euler characteristic is `V − E + F = 7 − 12 + 8 = 3`. Applying the familiar `2 − 2g` formula to infer a genus would already assume a closed, connected, orientable manifold. Geometric self-intersection is a separate property. [Geometry Central, manifoldness and boundaries](https://geometry-central.net/surface/surface_mesh/basics/)

For code organization, use an ordinary directed graph to locate tightly coupled modules, then trace a real operation. A one-off scan of 64 production TypeScript and Vue modules under `src` and `electron` found 131 distinct static runtime import edges and no directed cycles. It excludes type-only edges, dynamic loading, IPC, Vue reactions and Python. The missing Expand handshake crosses exactly such a runtime boundary. Moving code simply to shorten the 2,779-line `App.vue` would leave that contract broken. A more defensible split gives one module ownership of a decision that changes for one reason. The UI and desktop validator already share a single policy for Final render sample counts. [Parnas, *On the Criteria To Be Used in Decomposing Systems into Modules*](https://prl.khoury.northeastern.edu/img/p-tr-1971.pdf) · [Shared sample policy](../src/lib/final-quality.ts#L11)

## A workflow for Rasterform and other apps

1. **Before the edit, name the user-visible promise and its owner.** Find the existing type, function or data constraint that expresses it. For Expand, have the renderer and native receiver use the same set of supported names. The native process must still validate the origin and the incoming name. The project-file reader also lists the behaviors. Keep previously saved files as fixtures when changing a versioned format. [Project-file reader](../src/lib/editor-document.ts#L134)
2. **Start a bug fix with a failing observation.** Read the bytes, reopen the project, compare the camera, or query the committed database row. Keep the expected value independent of the code being changed. Run the earlier behavior tests and affected build commands after the fix.
3. **Review every added layer against a concrete change.** Which callers share this decision? Which part may vary independently? Is the old implementation still reachable? Keep separate validation at trust boundaries and centralize shared domain facts. A helper that merely renames one call and hides its side effects has a cost every time the next reader follows it.
4. **Evaluate the harness on the next task.** Pick a few historical pairs of related changes. For Rasterform, one pair could add a motion and then extend its export. Start both versions from the same commit with the same model, effort, tools and time budget. Vary one harness instruction or check. Give a fresh maintainer the follow-up without the first chat. Record whether both tasks pass independently written acceptance checks, time to find the owner, review and rework time, and model cost. Compare paired outcomes and ranges. Keep a change when it preserves behavior and reduces follow-up work at an acceptable cost. File count and added lines can help explain an outlier.

For example, a FastAPI endpoint backed by Postgres might promise that retrying the same request after a lost response creates one order. A reviewer can find which database constraint and transaction own that promise. Send two concurrent requests with the same account and idempotency key, then query the rows and compare the returned order IDs. Also try two different keys and the documented behavior for reusing one key with a different payload. This exercises the same reasoning as the ZIP test at a different boundary.

**A short brief to reuse**

> Find the existing owner of the behavior and name the promise this change must preserve. Make the smallest change that expresses it clearly. Demonstrate the result through the public interface and run the inherited checks. In the handoff, point to the decision the next maintainer would edit and the test that would catch a regression.
